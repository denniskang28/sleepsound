# 首版实现与验收说明

## 原型对应

设计基准是 `docs/ui/sleep-ui/sleep.dc.html` 中手机区域实际使用的样式与交互：深色背景 `#101722`，卡片 `#1B2533`，青绿色主操作 `#78C7BB`，鼾声琥珀色、疑似梦话紫色，页面边距 20 dp、卡片圆角 20–24 dp、56 dp 主按钮、底部面板与 Lucide 线性图标。使用本地 Archivo 与 Noto Sans SC 字体。

原型目录附带的 `_ds/.../readme.md` 是红白直角 Modernist 规范，与实际手机原型不一致；实现以用户指定的手机界面为准，没有应用该红白主题。

真实 Android 系统状态栏、导航手势、权限弹窗和通知由操作系统绘制，不复制原型中的假系统栏。日期、计时与报告来自实际数据；不启用原型的 60 倍速，也不在正常安装中注入示例记录。UI 测试中的合成夹具仅用于验证，不进入主程序。

## 数据口径

- 会话按开始时刻所在时区归档，跨午夜仍是一条会话。同一天多次监测分开保留。
- 有效时长仅累计成功采集并分析的非重叠音频窗口，暂停、静音输入异常、录音错误不累计。
- 声音事件的包络范围用于时间轴；识别命中时长用于累计，事件合并时的静默间隙及录音前后留白不计入鼾声时长。
- 录音片段最长约 124 秒，长事件按最多 120 秒的包络切分，控制内存和编码耗时。环形 PCM 缓冲最多 132 秒，约 4.2 MB；不将整晚 PCM 写盘。
- 至少两个分类窗口确认事件，最多合并 3 秒短间隔；当前模型窗口 15,600 点，约 0.975 秒。短促低置信人声可能被过滤，后续需用标注数据调优。
- 少于 3 小时标记数据不足。这里是继承原型的产品规则，不是医学或统计保证。
- 趋势按开始日期汇总。同一天多个合格会话的占比用累计鼾声 / 累计有效时长加权计算；数据不足会话不进入占比及标签平均。未监测的日期保持缺失。
- 误判修正后，该事件退出鼾声/疑似梦话统计，原事件和录音保留。撤销修正或恢复原结果可重新计入。
- 删除或到期清理录音只移除文件，事件与统计保留；收藏不能恢复已删除的文件。删除会话清除相关录音、事件和标签。

## 录音与恢复

从可见 Activity 请求权限后启动 `microphone` 前台服务。WorkManager 只负责到期清理，不用于整夜录音。麦克风服务不从开机广播或后台定时自动启动，不依赖系统自动重启服务。

运行时每约 5 秒保存采集心跳。进程终止后，不伪造直到下次打开之间的时长，保守终止于最后保存的心跳，并标记意外中断。最近不足 5 秒的计时、尚未闭合的声音事件可能未保存。编码采用临时文件后重命名；启动时清理无事件引用的遗留文件。

麦克风静音/占用回调和 AudioRecord 错误触发中断状态，每 3 秒重试。不同系统与厂商可能采用不同的音频仲裁行为，仍需真机覆盖。应用暂停时释放麦克风；不在监测期间播放历史录音，避免污染采集。

## 后续必须进行的真机验收

1. 目标机型整夜 8–10 小时，锁屏、省电/勿扰状态下的有效采集覆盖率、掉帧、耗电、温升和存储增长。
2. 来电、其他录音应用、系统麦克风开关、权限撤销、存储不足和进程终止后的时间轴与恢复。
3. 不同床头距离、手机方向、风扇/空调、电视/音乐、同床者等真实卧室样本。
4. 按用户划分的独立测试集，统计鼾声精确率/召回率、人声有效片段率、每小时误报和漏报。
5. 多日期和时区、同一天多会话、收藏保护、保留期限、修正后统计与清除操作。

模拟器测试能够验证代码链路，不能证明现实卧室识别准确度或厂商整夜保活。
